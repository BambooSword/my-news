| 位置 | 实际职责 |

## 与本次需求的差距

| 需求 | 旧版实现 | 处理判断 |
| --- | --- | --- |
| 国内/国际/科技分类、新闻列表 | 有分类和列表的雏形，直接调用教学 API | 保留产品概念，替换接口与组件实现 |
| 新闻摘要、明确来源、日期倒序、原文跳转 | 部分列表显示时间/作者；详情读取 `pagecontent` 全文 HTML | 按摘要聚合需求重做，不能保留全文嵌入方式 |
| PC/手机适配 | 两套重复组件；1224px 边界条件重叠 | 保留适配目标，改为共享组件和响应式布局 |
| 每日新闻更新和去重 | 没有自己的后台任务或存储 | 使用服务端采集、稳定标识和持久存储 |
| Medium 等深度文章精选 | 没有 | 需要独立精选数据和导读内容 |
| 邮箱订阅与每日简报 | 没有；产品导航中的“邮箱”只是外链 | 需要确认订阅、退订和邮件服务，不能视为现成功能 |
| 收藏单词/金句、英美 IPA、学习笔记 | 仅收藏整篇新闻 | 保留“个人收藏”的产品概念，不复用旧数据结构 |
| 账号隔离与云同步 | 客户端保存 userid，调用远端收藏接口 | 使用服务端认证和按账号隔离的数据库记录 |
| 版权/免责声明/关于本站 | 旧页脚不足以覆盖新需求 | 新增或沿用现有知简页面 |

## 不应直接迁移的实现

1. `pc_header.js` / `mobile_header.js` 把用户名、密码拼接到 HTTP GET URL，并打印表单内容。新版不应继承这一认证方式。
2. PC 端使用 `localStorage.userid` 判断登录状态；登录成功提示先于异步结果，不能当作可靠认证。
3. PC/移动详情对第三方 `pagecontent` 使用 `dangerouslySetInnerHTML`，没有在这些组件中看到清洗处理。它既不符合“只展示摘要”的要求，也引入不可信 HTML 风险。
4. 收藏和评论写操作使用 GET 请求；查询参数直接拼接，缺少这里可见的错误处理与输入编码。
5. `pc_products.js` 的门户产品导航、Redux 计数器、头像上传示例、轮播素材不是新需求；默认仅留在历史备份，不带入新版。
6. `index.html` 的 viewport 声明有拼写错误并禁止缩放；不作为新版可访问性基础。
